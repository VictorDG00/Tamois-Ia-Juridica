Normalização aplicada pelo sistema após a resposta

  • 🔍 Validação de campos: apenas os 8 campos definidos são aceitos — campos extras são ignorados.
  • ✂️ Truncamento: cada campo é cortado em 200 caracteres (menor que os outros fluxos — dados devem ser curtos e objetivos).
  • 🔄 Normalização de nulos: campos ausentes, vazios ou com strings vazias são convertidos para null.
  • 🔧 Recuperação de JSON quebrado: igual aos outros fluxos — tenta extrair JSON de markdown ou do texto livre.
Regra Principal — Não inferir ESCOPO
⚠️ A regra mais importante deste fluxo: o modelo não pode inferir ou completar informações que não estejam explicitamente no texto. Se o valor não está no contrato, o campo deve ser null — não uma estimativa, não "a combinar", não "não informado".
  • ✅ Campo presente no texto → copiar literalmente, sem parafrasear
  • ✅ Campo ausente no texto → retornar null (sem aspas)
  • 🚫 Campo parcialmente presente → não completar com inferência. Ex: se menciona "R$ 5.000" sem periodicidade, copiar apenas "R$ 5.000" sem adicionar "/mês"
  • 🚫 Tipo de documento diferente (notificação, petição) → alguns campos serão naturalmente null. Normal e esperado.
Dicas para Testar TESTE
  • 1️⃣ Teste com contrato completo — todos os 8 campos presentes. Verifique se o modelo extrai sem parafrasear.
  • 2️⃣ Teste com contrato incompleto — faltando 3-4 campos. O modelo deve retornar null sem inventar.
  • 3️⃣ Teste com petição (sem contratante/contratada/valor) — quase todos os campos devem ser null.
  • 4️⃣ Atenção ao campo objeto: contratos longos têm parágrafos extensos — verifique se o modelo resume ou copia literal (deve copiar literal até 150 chars).
✅ Critério de aprovação: zero campos inventados + todos os campos presentes extraídos literalmente. null para ausentes é resultado correto, não um erro.
