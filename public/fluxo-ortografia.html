Prompt do Usuário (completo) USER

Enviado como role: "user" — o bloco em azul é substituído pelo texto do documento

Você é um revisor jurídico especializado em direito brasileiro.
REGRA FUNDAMENTAL: Só reporte itens com CERTEZA ABSOLUTA. Em caso de dúvida, não reporte.
Prefira lista pequena e precisa a lista grande com itens duvidosos.
O texto contém parágrafos indexados (ex: [Paragrafo 0] ...).

Analise APENAS erros ortográficos e gramaticais inequívocos.
NÃO reporte: jargão jurídico, latinismos, termos técnicos, variações aceitas, palavras corretas em contexto jurídico.
Reporte TODOS os erros encontrados, sem limite de quantidade.

Retorne SOMENTE JSON válido:
{"orthography":[{"original":"...","suggestion":"...","reason":"..."}]}
Se não houver erros, retorne: {"orthography":[]}

Texto:
[TEXTO DO DOCUMENTO — parágrafos indexados, máx 20.000 chars]
Contrato de Saída (JSON) OUTPUT

O modelo deve retornar exatamente este formato

{
  "orthography": [
    {
      "original":    "texto exato com o erro",     // obrigatório, não pode ser vazio
      "suggestion":  "texto corrigido",              // obrigatório, não pode ser vazio
      "reason":      "justificativa breve"          // opcional mas recomendado
    }
  ]
}

// Se não houver erros:
{ "orthography": [] }

Regras de normalização aplicadas pelo sistema após a resposta

  • 🔍 Filtragem de itens inválidos: qualquer item sem original ou sem suggestion é descartado silenciosamente.
  • ✂️ Truncamento de campos: cada campo (original, suggestion, reason) é cortado em 600 caracteres.
  • 🔧 Recuperação de JSON quebrado: se o modelo retornar markdown (```json ... ```), o sistema extrai o JSON interno. Se ainda assim falhar, extrai o primeiro objeto JSON encontrado no texto.
  • 📋 Sem limite de itens: todos os erros retornados pelo modelo são exibidos. O prompt instrui o modelo a reportar todos os erros sem limite.
Formato do Texto de Entrada INPUT

Como o documento chega ao modelo após processamento do DocxExtractor

[Paragrafo 0] CONTRATO DE PRESTAÇÃO DE SERVIÇOS

[Paragrafo 1] Pelo presente instrumento particular, as partes abaixo

e condições a seguir estabelecidas.

[Paragrafo 2] CLÁUSULA PRIMEIRA — DAS PARTES
...
ℹ️ Cada parágrafo recebe um índice numérico sequencial começando em 0. O modelo deve usar esse índice como paragraph_id nos fluxos que precisam localizar o parágrafo (insights). No fluxo de ortografia, o índice é informado mas não é solicitado no output.
Regras de Escopo — O que NÃO reportar ESCOPO
⚠️ Contexto crítico: textos jurídicos usam termos, grafias e construções que seriam "erros" em português comum mas são corretos no contexto forense. O modelo precisa entender isso.
  • 🚫 Latinismos: in dubio pro reo, pacta sunt servanda, ad referendum, ex officio, habeas corpus, sub judice — nunca reportar como erro.
  • 🚫 Termos técnicos jurídicos: mesmo que incomuns ou pouco usados fora do direito. Dúvida = não reportar.
  • 🚫 Variações aceitas: formas que têm aceitação em alguma gramática ou uso consolidado — não reportar.
  • 🚫 Erros de redação: ambiguidade, imprecisão, cláusulas mal estruturadas — esses pertencem ao fluxo 3 (Redação), não aqui.
  • ✅ Reportar apenas: erros de grafia, concordância errada, crase errada, acentuação incorreta — quando inequívocos.
Dicas para Testar e Iterar TESTE
  • 1️⃣ Teste com um contrato que você sabe que tem erros específicos — verifique se o modelo encontra exatamente esses erros e não outros.
  • 2️⃣ Teste com um contrato limpo (sem erros) — o modelo deve retornar {"orthography":[]} e não inventar correções.
  • 3️⃣ Inclua latinismos e termos técnicos propositalmente — verifique que o modelo não os reporta como erro.
  • 4️⃣ Observe se o modelo mistura erros ortográficos com sugestões de redação — isso é um vazamento de escopo que o prompt deve corrigir.
  • 5️⃣ Ao testar via API diretamente, use temperatura 0.1 para replicar o comportamento real do sistema.
✅ Critério de aprovação: 0 falsos positivos em texto jurídico correto + todos os erros reais encontrados em texto com erros propositais. Priorize precisão sobre recall.
