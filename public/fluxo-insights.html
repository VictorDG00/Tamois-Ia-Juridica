Classificação de Risco 3 NÍVEIS

O modelo deve classificar cada insight em exatamente um destes níveis

high — Alto
Nulidade, inconstitucionalidade, violação de direito fundamental.
Ex: cláusula que viola o CDC em contrato de consumo, renúncia a direito irrenunciável.
medium — Médio
Cláusula abusiva confirmada, ambiguidade que gera conflito real, falta de elemento essencial.
Ex: prazo de recurso ambíguo, multa sem definição de base de cálculo.
low — Baixo
Imprecisão terminológica clara, redundância evidente.
Ex: uso de "rescisão" onde tecnicamente seria "resolução".
ℹ️ Se o modelo retornar um risk_level diferente de low, medium ou high, o sistema substitui automaticamente por medium. O prompt deve forçar o uso exato dessas três strings.
Mensagem System SYSTEM 
Responda somente em JSON válido.
Prompt do Usuário (completo) USER

O bloco em azul é substituído pelo texto real do documento

Você é um revisor jurídico especializado em direito brasileiro.
REGRA FUNDAMENTAL: Só reporte itens com CERTEZA ABSOLUTA. Em caso de dúvida, não reporte.
Prefira lista pequena e precisa a lista grande com itens duvidosos.
O texto contém parágrafos indexados (ex: [Paragrafo 0] ...).

Analise APENAS riscos jurídicos baseados em norma específica e identificável.
NÃO reporte: especulações, riscos hipotéticos, interpretações forçadas.
Classifique risco_level como: high (nulidade, inconstitucionalidade, violação de direito fundamental),
medium (cláusula abusiva confirmada, ambiguidade que gera conflito real, falta de elemento essencial),
low (imprecisão terminológica clara, redundância evidente).
Reporte TODOS os riscos reais, sem limite de quantidade.
Use paragraph_id com o número inteiro do parágrafo de origem.

Retorne SOMENTE JSON válido:
{"legal_insights":[{"topic":"...","insight":"...","risk_level":"low|medium|high","paragraph_id":INT}]}
Se não houver riscos, retorne: {"legal_insights":[]}

Texto:
[TEXTO DO DOCUMENTO — parágrafos indexados, máx 20.000 chars]
Contrato de Saída (JSON) OUTPUT 
{
  "legal_insights": [
    {
      "topic":        "nome do risco (ex: Cláusula Abusiva)",  // obrigatório
      "insight":      "descrição do risco identificado",       // obrigatório
      "risk_level":   "low" | "medium" | "high",             // exatamente uma das três strings
      "paragraph_id": 3                                       // índice inteiro do parágrafo — ex: 3 para [Paragrafo 3]
    }
  ]
}

Normalização aplicada pelo sistema após a resposta

  • 🔍 Filtragem: itens sem topic ou sem insight são descartados.
  • 🏷️ Validação de risk_level: se o valor não for low, medium ou high, substitui por medium automaticamente.
  • 📍 paragraph_id: convertido para inteiro. Valores negativos, nulos ou inválidos viram -1 (indica parágrafo não localizado).
  • ⚖️ Disclaimer automático: o sistema adiciona ao final de cada insight o texto abaixo. O campo insight é truncado para caber dentro dos 600 chars totais.
Análise informativa que não substitui consultoria jurídica profissional.
⚠️ O disclaimer é adicionado sempre, automaticamente, pelo código — não deve ser incluído no prompt. Isso garante que a obrigação legal aparece em todos os insights independentemente do que o modelo retornar.
Como o paragraph_id funciona ÂNCORA

O paragraph_id permite que a interface exiba o insight vinculado ao parágrafo correto do documento. Quando o usuário clica em um insight de risco alto, a UI destaca o parágrafo de origem.

// Texto enviado ao modelo:
[Paragrafo 0] CONTRATO DE PRESTAÇÃO DE SERVIÇOS
[Paragrafo 1] ...qualificação das partes...
[Paragrafo 2] CLÁUSULA PRIMEIRA — OBJETO
[Paragrafo 3] A CONTRATADA deverá entregar em prazo razoável...
                                  ^^^^^^^^^^^^^^^^^^^
// Insight gerado:
// paragraph_id: 3  →  o insight se refere ao [Paragrafo 3]
Dicas para Testar TESTE
  • 1️⃣ Insira uma cláusula claramente abusiva — o modelo deve identificar e classificar como high ou medium.
  • 2️⃣ Insira um contrato equilibrado e bem redigido — o modelo deve retornar {"legal_insights":[]} ou poucos insights de risco baixo.
  • 3️⃣ Verifique se os paragraph_id retornados correspondem ao parágrafo correto do texto enviado.
  • 4️⃣ O modelo não deve especular sobre riscos hipotéticos ("pode causar problemas futuramente"). Apenas riscos baseados em norma concreta.
  • 5️⃣ Verifique o topic — deve ser um título curto e objetivo, não uma frase longa. Ex: "Cláusula de Não Concorrência Abusiva", não "A cláusula 7 pode ser considerada abusiva por...".
✅ Critério de aprovação: zero riscos inventados + risco_level correto por critério definido + paragraph_id preciso + topic conciso.
