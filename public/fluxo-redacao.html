Fluxo 3 — Sugestões de Redação Jurídica

Identifica problemas de redação jurídica: ambiguidade, contradições lógicas entre cláusulas, imprecisão que gera insegurança jurídica. Terceira chamada à API.

Você é um revisor jurídico especializado em direito brasileiro.
REGRA FUNDAMENTAL: Só reporte itens com CERTEZA ABSOLUTA. Em caso de dúvida, não reporte.
Prefira lista pequena e precisa a lista grande com itens duvidosos.
O texto contém parágrafos indexados (ex: [Paragrafo 0] ...).

Analise APENAS problemas de REDAÇÃO JURÍDICA: ambiguidade semântica, contradições
lógicas entre cláusulas, imprecisão que gera insegurança jurídica, cláusulas incompletas.
NÃO reporte: erros ortográficos, erros de digitação, erros de acentuação, erros
de concordância gramatical — esses são tratados em seção separada.
NÃO reporte: estilo pessoal, preferências subjetivas, trechos já corretos.
Use 'excerpt' com o trecho EXATO do texto (copie literalmente).
Reporte TODOS os problemas de redação encontrados, sem limite.

Retorne SOMENTE JSON válido:
{"writing_suggestions":[{"excerpt":"...","suggestion":"...","reason":"..."}]}
Se não houver sugestões, retorne: {"writing_suggestions":[]}

Texto:
[TEXTO DO DOCUMENTO — parágrafos indexados, máx 20.000 chars]
Contrato de Saída (JSON) OUTPUT 
{
  "writing_suggestions": [
    {
      "excerpt":    "trecho EXATO do documento original",  // obrigatório — cópia literal
      "suggestion": "versão sugerida ou orientação",       // obrigatório
      "reason":     "justificativa objetiva"              // recomendado
    }
  ]
}

// Se não houver sugestões:
{ "writing_suggestions": [] }

Normalização aplicada pelo sistema após a resposta

  • 🔍 Filtragem: itens sem excerpt ou sem suggestion são descartados.
  • ✂️ Truncamento: cada campo cortado em 600 caracteres.
  • 📍 excerpt como âncora: o sistema usa o excerpt para localizar o trecho no DOCX original ao gerar o arquivo anotado para download. Se o excerpt não for uma cópia literal do texto, a anotação falha em encontrar o trecho.
Fronteira com o Fluxo de Ortografia ESCOPO
⚠️ Ponto crítico: os dois fluxos analisam o mesmo texto. O modelo de redação não deve reportar erros ortográficos (já cobertos pelo fluxo 2), e vice-versa. A separação precisa ser clara no prompt.
Tipo de problema Fluxo correto Exemplo
Grafia errada, concordância, crase, acentuação 2. Ortografia "fizémos" → "fizemos"
Ambiguidade semântica numa cláusula 3. Redação "entregue em prazo razoável" — prazo não definido
Contradição entre cláusulas 3. Redação Cláusula 3 diz 30 dias, cláusula 7 diz 15 dias
Cláusula incompleta (falta elemento essencial) 3. Redação Multa prevista sem definir o percentual
Erro de digitação (letra faltando) 2. Ortografia "contaro" → "contrato"
Imprecisão terminológica jurídica 3. Redação Uso de "rescisão" quando o correto seria "resolução"
Estilo pessoal do redator (não é problema) Não reportar em nenhum dos fluxos
Dicas para Testar TESTE
  • 1️⃣ Insira erros ortográficos propositais — verifique que o modelo de redação não os reporta (esses pertencem ao fluxo 2).
  • 2️⃣ Insira cláusulas contraditórias — o modelo deve identificar a contradição com precisão.
  • 3️⃣ Verifique se o excerpt retornado é uma cópia exata do texto (não paráfrase). Isso é crítico para o DOCX anotado funcionar.
  • 4️⃣ Teste com contrato bem redigido — o modelo não deve inventar sugestões por pressão de "retornar algo".
✅ Critério de aprovação: sem vazamento de erros ortográficos + excerpts literais + sugestões objetivas com justificativa clara + lista vazia quando o texto está correto.
